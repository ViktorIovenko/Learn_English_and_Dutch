# ParallelLingvo app-domain and authentication migration

This document is the deployment/agent handoff for moving the learning application from
`learn.iovenko.eu` to `app.parallellingvo.app` and enabling modern website login.

## Target architecture

- `https://parallellingvo.app/` — static public website, blog, SEO/AI pages.
- `https://app.parallellingvo.app/` — Flask learning application.
- `https://learn.iovenko.eu/` — legacy hostname, redirects permanently to the new app hostname.
- Google and Telegram website login start from the public website and finish inside the app.
- Telegram website login uses the current OpenID Connect Authorization Code flow with PKCE.
- Telegram Mini App login continues to use signed Telegram `initData` verified with `TELEGRAM_BOT_TOKEN`.
- Both Telegram entry points resolve to the same ParallelLingvo account by Telegram numeric user id.

## Prepared in the repository

1. `nginx/app.parallellingvo.conf` proxies `app.parallellingvo.app` to `learn-words:7001`.
2. `nginx/learn.conf` redirects the old application hostname to the new app hostname.
3. `nginx/parallellingvo.conf` redirects the static site's `/auth/google` and `/auth/telegram` buttons to the app.
4. `app/web_auth.py` implements Google OIDC and modern Telegram OIDC login.
5. Telegram OIDC uses discovery at `https://oauth.telegram.org/.well-known/openid-configuration`, Authorization Code flow and PKCE S256.
6. Telegram OIDC requests `openid profile telegram:bot_access`; phone access is intentionally not requested.
7. `auth_identities` maps provider identities to the existing `users.user_id`.
8. Existing Telegram numeric user IDs are preserved when possible so old lessons/progress remain attached.
9. Browser-controlled `?uid=` / localStorage user identity / `X-User-Id` was removed from `app/templates/base.html`.
10. Page API requests wait for server-verified Telegram Mini App auth or an existing Flask session before they run.
11. `X-User-Id` is stripped server-side by default as defense in depth.
12. `bot/auth.py` no longer creates Mini App URLs with `?uid=` and no longer contains the personal fallback password.
13. `.env.example` lists production bot, Telegram OIDC and Google OIDC variables.

## Two official Telegram authentication flows

### A. Website -> Telegram OpenID Connect

```text
parallellingvo.app
  -> /auth/telegram
  -> Telegram OpenID Connect
  -> /auth/telegram/callback
  -> Flask session
  -> app.parallellingvo.app
```

This is the modern browser login flow. It uses the Client ID and Client Secret generated by BotFather for the branded ParallelLingvo bot.

### B. Telegram bot -> Mini App

```text
ParallelLingvo bot
  -> Main App / Menu Button
  -> app.parallellingvo.app
  -> Telegram WebApp initData
  -> POST /api/auth/login_webapp
  -> server verifies initData with TELEGRAM_BOT_TOKEN
  -> Flask session
```

Do not replace Mini App `initData` verification with browser OIDC. These are separate official mechanisms for different entry points.

## Server steps still required

### 1. Confirm DNS

The DNS record must resolve:

```text
app.parallellingvo.app -> 204.168.186.69
```

### 2. Issue TLS certificate

Issue a Let's Encrypt certificate for:

```text
app.parallellingvo.app
```

The nginx config expects:

```text
/etc/letsencrypt/live/app.parallellingvo.app/fullchain.pem
/etc/letsencrypt/live/app.parallellingvo.app/privkey.pem
```

### 3. Install nginx vhost

Enable:

```text
nginx/app.parallellingvo.conf
```

Keep the public-site vhost and legacy redirect vhost enabled. Validate nginx before reload.

### 4. Update production `.env`

At minimum:

```env
SITE_BASE_URL=https://parallellingvo.app
APP_BASE_URL=https://app.parallellingvo.app
PUBLIC_BASE_URL=https://app.parallellingvo.app
ALLOW_LEGACY_UID_AUTH=0
FLASK_SECRET=<strong-random-secret>

TELEGRAM_BOT_TOKEN=<new ParallelLingvo bot token>
TELEGRAM_BOT_USERNAME=<new bot username without @>
TELEGRAM_OIDC_CLIENT_ID=<BotFather Client ID>
TELEGRAM_OIDC_CLIENT_SECRET=<BotFather Client Secret>

GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
```

Never commit real secrets.

### 5. Rebuild application container

`Authlib` is required, so rebuild the Flask image/container rather than only restarting it.

After start verify:

```text
https://app.parallellingvo.app/auth/status
```

An anonymous browser should receive `authenticated: false`.

```text
https://app.parallellingvo.app/auth/google/callback
```

```text
https://parallellingvo.app/auth/google
  -> Google
  -> callback
  -> https://app.parallellingvo.app/
```

## Telegram BotFather setup

### Mini Apps

Enable both where desired:

```text
Main App URL: https://app.parallellingvo.app/
Menu Button URL: https://app.parallellingvo.app/
```

Keep Same-Origin Restriction enabled.

### Login Widget -> OpenID Connect Login

Use the modern OpenID Connect mode, not the legacy iframe widget.

Register exactly:

```text
Redirect URI:
https://app.parallellingvo.app/auth/telegram/callback

Trusted Origins:
https://parallellingvo.app
https://app.parallellingvo.app
```

Keep signing algorithm:

```text
RS256
```

Copy the displayed Client ID and Client Secret into the server `.env` as:

```env
TELEGRAM_OIDC_CLIENT_ID=...
TELEGRAM_OIDC_CLIENT_SECRET=...
```

The application requests:

```text
openid profile telegram:bot_access
```

It does not request the user's phone number.

## Existing Telegram users

Historically `users.user_id` is the Telegram numeric ID. Telegram OIDC `profile` claims include the Telegram numeric `id`; the auth layer preserves that ID as the internal user id for Telegram accounts. This lets both OIDC and Mini App login reach the same existing lessons/progress without a destructive database migration.

New Google-only accounts receive provider-neutral ids such as:

```text
u_<uuid>
```

Provider mappings live in `auth_identities`.

Do not delete or rewrite existing `users`, `words`, progress, lesson, or translation data during deployment.

## Security status

Production must keep:

```env
ALLOW_LEGACY_UID_AUTH=0
```

Never restore browser-controlled identity through:

```text
?uid=
localStorage user id
X-User-Id
```

Telegram Mini App identity must come from verified `initData`; website Telegram identity must come from a validated OIDC ID token.

## End-to-end tests

Run all of these before merging/deploying:

1. Anonymous `GET /auth/status` -> not authenticated.
2. Google OIDC login -> callback -> app session.
3. Telegram OIDC login -> callback -> app session.
4. Telegram OIDC profile resolves to the expected Telegram numeric user id.
5. `telegram:bot_access` authorization succeeds without requesting phone permission.
6. Telegram Mini App login verifies `initData` using the new bot token.
7. The same Telegram account sees the same lessons through OIDC and Mini App entry points.
8. Existing Telegram user's historical data still loads.
9. New Google-only account works.
10. `learn.iovenko.eu` redirects to `app.parallellingvo.app` preserving safe path/query information.
11. Logout clears the session and a second login works.

## Recommended deployment order

1. DNS resolves.
2. Issue TLS certificate.
3. Enable app nginx vhost.
4. Update `.env` domains and `FLASK_SECRET`.
5. Add the new bot token and username.
6. Configure BotFather Main App/Menu Button.
7. Configure BotFather OpenID Connect Redirect URI and Trusted Origins.
8. Add Telegram OIDC Client ID/Secret to `.env`.
9. Add Google OIDC credentials.
10. Rebuild application container.
11. Test app and `/auth/status`.
12. Test Google login.
13. Test Telegram OIDC browser login.
14. Test Telegram Mini App `initData` login.
15. Verify both Telegram methods resolve to the same existing user data.
16. Test legacy-domain redirect.
