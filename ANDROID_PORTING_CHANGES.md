# Изменения для переноса в Android

Актуально на: 6 июля 2026 года.

Этот файл — журнал серверных, Telegram- и Web-изменений, которые необходимо учитывать при обновлении Android-приложения. После каждого изменения семейной логики или регистрации дополнять этот документ.

## 1. Регистрация и тип аккаунта

Реализовано на сервере и в Telegram:

- Бот определяет `language_code` интерфейса Telegram и на этом языке предлагает оставить такой же язык приложения.
- При подтверждении обнаруженный язык сохраняется; при отказе бот показывает список всех поддерживаемых языков.
- После ручного выбора остальные вопросы регистрации отображаются уже на выбранном языке приложения.
- Затем пользователь выбирает тип аккаунта:
  - `standard` — обычный аккаунт;
  - `child` — детский аккаунт.
- Пока выбор не завершён, сервер возвращает `account_type: "pending"` и `needs_account_type: true`.
- Язык Telegram используется для локализации вопросов бота.
- Старые аккаунты без выбранного типа однократно мигрируют в `standard`.
- Новые аккаунты после миграции продолжают создаваться как `pending`.
- Выбранный тип аккаунта нельзя свободно менять после завершения регистрации.

Android сейчас уже содержит:

- `AccountTypeFragment`;
- переход на выбор типа через `needsAccountType`;
- запрос `POST /api/account/type`.

Что проверить при переносе:

- Android не должен пропускать `AccountTypeFragment`, если `needs_account_type = true`.
- После выбора типа нужно повторно запросить `/api/me` и обновить доступную навигацию.
- Для детского аккаунта после выбора типа нужно сразу предложить экран семейного подключения.
- Все строки должны присутствовать во всех поддерживаемых Android locale: `en`, `ru`, `nl`, `de`, `fr`, `es`, `it`, `pt`, `pl`, `uk`.

## 2. Новый семейный сценарий через Telegram

Текущий основной сценарий больше не использует браузерную авторизацию родителя.

Правильный поток:

1. Детский аккаунт запрашивает код через `GET /api/family/pairing-code`.
2. Сервер возвращает Telegram deep link вида:

   `https://t.me/IovenkoFamily_bot?start=family_<short_code>`

3. QR-код должен содержать именно `pairing_url` из ответа сервера.
4. Рядом с QR необходимо показать копируемую ссылку и системную кнопку «Поделиться».
5. Родитель сканирует QR или открывает полученную ссылку.
6. Открывается Telegram-бот родителя.
7. Бот показывает имя ребёнка и кнопки «Подключить» / «Отмена».
8. Связь создаётся только после нажатия «Подключить».

Важно:

- Не открывать `/family/link` как основной сценарий.
- Не требовать авторизацию родителя во внешнем браузере.
- Не извлекать старый query-параметр `token` из QR для нового потока.
- Код действует 10 минут.
- Повторный запрос кода инвалидирует предыдущий код ребёнка.
- Старый HTTPS-сценарий оставлен сервером только для обратной совместимости.

Android сейчас использует старую логику в:

- `MainActivity.handleFamilyLinkIntent()` — обрабатывает `https://learn.iovenko.eu/family/link`;
- `LanguageSettingsFragment.startFamilyQrScan()`;
- `LanguageSettingsFragment.linkChildFromQr()` — извлекает `token` и напрямую вызывает `POST /api/family/link`.

Что изменить в Android:

- Детский аккаунт продолжает генерировать QR из `PairingCodeResponse.pairingUrl`.
- Добавить отображение полного `pairingUrl`, копирование в буфер и Android Share Sheet.
- Для обычного аккаунта убрать обязательное сканирование QR внутри Android: QR должен открывать Telegram.
- Старый scanner можно оставить временно только как legacy fallback.
- Android deep-link `/family/link` не должен быть основным способом подключения.

## 3. Ограничения семейных связей

- Один ребёнок может иметь максимум 5 подключённых взрослых.
- Связь уникальна по паре `(parent_user_id, child_user_id)`.
- Один и тот же взрослый не должен создавать дубликат связи.
- Шестой взрослый получает ошибку `parent_limit_reached`.
- Детский аккаунт не может выступать родителем.
- Пользователь не может подключить самого себя.
- Просроченный код возвращает `invalid_or_expired_pairing_code`.

Android должен показывать понятные локализованные сообщения для ошибок:

- `parent_limit_reached`;
- `child_cannot_be_parent`;
- `cannot_link_self`;
- `invalid_or_expired_pairing_code`;
- `child_account_not_found`.

## 4. Что видит ребёнок

`GET /api/family` для детского аккаунта возвращает массив `parents`.

Android должен показывать:

- всех подключённых взрослых;
- имя и username, если доступны;
- количество подключённых взрослых: `N из 5`;
- QR-код Telegram;
- копируемую Telegram-ссылку;
- кнопку обновления ссылки;
- кнопку системного «Поделиться».

Telegram-команда `/family` уже показывает новый QR, ссылку и подключённых взрослых.

## 5. Родительский дашборд

Серверный контракт `GET /api/family/dashboard` расширен.

Теперь каждый элемент `children[]` содержит:

```json
{
  "user_id": "...",
  "display_name": "...",
  "parents": [
    {
      "user_id": "...",
      "display_name": "...",
      "username": "...",
      "first_name": "...",
      "last_name": "...",
      "created_at": "..."
    }
  ],
  "summary": {},
  "latest_progress": {},
  "daily": []
}
```

Web-поведение, которое нужно повторить в Android:

- Удалён выпадающий список детей.
- Дети показываются прямоугольными карточками.
- Нажатие карточки выбирает ребёнка и обновляет метрики, график и последний прогресс.
- На карточке отображаются все взрослые, подключённые к этому ребёнку.
- Кнопка «Отключить» расположена в одной строке с именем ребёнка.
- Отключается только связь текущего взрослого с выбранным ребёнком.

Android сейчас не соответствует этому поведению:

- `fragment_parent_dashboard.xml` содержит `spinner_child`;
- `ParentDashboardFragment` использует `spinnerChild`;
- кнопка отключения находится отдельно;
- `ChildDashboardDto` не содержит поле `parents`.

Необходимые Android-изменения:

- Добавить в `ChildDashboardDto`:

  `@SerializedName("parents") val parents: List<FamilyMemberDto> = emptyList()`

- Заменить `spinnerChild` горизонтальным списком карточек, например `RecyclerView`.
- Добавить адаптер карточек детей с выбранным состоянием.
- В строке карточки разместить имя ребёнка и кнопку отключения.
- Под именем показывать последнюю активность и список взрослых.
- Выбор карточки должен вызывать существующий `viewModel.selectChild(childId)`.
- После отключения обновлять список и выбирать первую оставшуюся карточку.

## 6. Администрирование семейных связей

В Web-админке добавлены:

- точное отображение пары взрослый → ребёнок;
- кнопка удаления конкретной связи;

Тело запроса:

```json
{
  "parent_user_id": "...",
  "child_user_id": "..."
}
```

Если Android-админка должна поддерживать семейные связи, добавить те же данные и удаление конкретной пары. Обычному Android-клиенту этот endpoint не нужен.

## 7. Актуальные API-контракты

### `GET /api/me`

Семейные поля:

- `account_type`: `pending | standard | child`;
- `needs_account_type`: boolean;
- `is_parent`: boolean;
- `children_count`: integer;
- `ui_language`;
- `detected_ui_language`;
- `ui_language_override`.

### `POST /api/account/type`

```json
{"account_type": "standard"}
```

или:

```json
{"account_type": "child"}
```

### `GET /api/family`

Возвращает:

- `account_type`;
- `needs_account_type`;
- `is_parent`;
- `children[]`;
- `parents[]`.

### `GET /api/family/pairing-code`

Возвращает:

```json
{
  "ok": true,
  "code": "short_code",
  "token": "legacy_signed_token",
  "pairing_url": "https://t.me/IovenkoFamily_bot?start=family_short_code",
  "expires_in": 600
}
```

Для нового Android UI использовать `code`, `pairing_url` и `expires_in`. Поле `token` является legacy.

### `GET /api/family/dashboard`

Query:

- `days`: `7 | 30 | 90`;
- `tz_offset`: смещение часового пояса в минутах.

Главное изменение: `children[].parents[]`.

### `DELETE /api/family/children/{child_id}`

Удаляет только связь текущего взрослого с выбранным ребёнком.

## 9. Проверочный сценарий после переноса

1. Создать новый детский аккаунт.
2. Убедиться, что Android показывает QR с `t.me`, а не `learn.iovenko.eu/family/link`.
3. Скопировать и отправить ссылку родителю.
4. Открыть ссылку родительским Telegram-аккаунтом.
5. Нажать «Отмена» — связь не должна появиться.
6. Повторить и нажать «Подключить» — должна появиться ровно одна связь.
7. Проверить список взрослых на аккаунте ребёнка.
8. Подключить до 5 взрослых.
9. Проверить отказ шестому взрослому.
10. Открыть родительский дашборд и переключать детей карточками.
11. Убедиться, что каждый родитель видит остальных взрослых выбранного ребёнка.
12. Отключить ребёнка и проверить удаление только одной конкретной связи.

## 11. 2026-07-04 — серия дней обучения

Реализовано в Telegram Web App:

- на главной странице отображается огонёк и текущая серия дней обучения без пропусков;
- серия считается по локальным календарным дням пользователя;
- если пользователь занимался вчера, но ещё не занимался сегодня, серия сохраняется до конца текущего дня;
- после полного пропущенного дня серия сбрасывается в `0`;
- любое событие обучения из `progress_events` засчитывает день как учебный.

Новый API для главной страницы Android:

`GET /api/learning/streak?tz_offset=120`

```json
{
  "ok": true,
  "learning_streak_days": 7,
  "timezone_offset_minutes": 120
}
```

`tz_offset` — локальное смещение устройства от UTC в минутах, диапазон ограничен от `-840` до `840`.

Контракт `GET /api/family/dashboard` расширен: в `children[].summary` добавлено поле:

```json
{
  "learning_streak_days": 7
}
```

Это поле содержит текущую серию ребёнка за всё время и не зависит от выбранного периода `days=7|30|90`.

Для переноса в Android необходимо:

- добавить `learningStreakDays` с `@SerializedName("learning_streak_days")` в DTO ответа серии и в summary ребёнка;
- добавить метод `GET api/learning/streak` с query-параметром `tz_offset` в `ApiService.kt` и репозиторий;
- на главном экране показать `🔥` и количество дней подряд;
- в `ParentDashboardFragment` показать `🔥` и `learningStreakDays` выбранного ребёнка;
- добавить строки во все `values-*/strings.xml`;
- передавать актуальный timezone offset устройства при каждом запросе.

Критерии проверки Android:

1. При активности три последовательных дня отображается `🔥 3`.
2. Утром следующего дня до первого занятия серия всё ещё равна `3`.
3. После занятия в этот день серия становится `4`.
4. После полного пропущенного дня отображается `🔥 0`.
5. Родитель видит ту же серию для выбранного ребёнка независимо от периода дашборда.

## 12. 2026-07-04 — прогресс слов по языкам на карточке урока

На главной странице Telegram Web App каждая карточка урока теперь показывает отдельный индикатор батареи для каждого выбранного языка обучения, кроме текущего языка интерфейса.

Правила подсчёта:

- слово считается выученным после правильной сборки слова по буквам (`reason = "answer_ok"`);
- статистика разделяется по `lesson`, `lang` и `word_id`;
- повторная правильная сборка того же слова на том же языке не увеличивает счётчик;
- правильная сборка этого слова на другом языке учитывается отдельно;
- язык интерфейса (`ui_language`) полностью исключается из списка индикаторов;
- знаменатель содержит только слова урока, у которых заполнен текст на соответствующем языке.
- если в конкретном уроке нет ни одного слова на выбранном языке, этот язык отсутствует в `language_progress` и батарея для него не показывается;

Контракт `GET /api/lessons` расширен. Каждый урок содержит:

```json
{
  "lesson": "Animals",
  "words_count": 10,
  "language_progress": [
    {
      "code": "nl",
      "name": "Dutch",
      "native": "Nederlands",
      "learned_words": 4,
      "total_words": 10,
      "percent": 40
    },
    {
      "code": "ru",
      "name": "Russian",
      "native": "Русский",
      "learned_words": 7,
      "total_words": 10,
      "percent": 70
    }
  ]
}
```

Событие прогресса из режима сборки слова должно обязательно передавать:

```json
{
  "scope": "learn",
  "type": "progress",
  "state": {
    "lesson": "Animals",
    "word_id": 123,
    "lang": "nl",
    "reason": "answer_ok"
  }
}
```

Для Android необходимо:

- добавить `languageProgress` в DTO урока;
- добавить DTO с полями `code`, `name`, `native`, `learnedWords`, `totalWords`, `percent`;
- убедиться, что событие правильной сборки содержит точный `lang` и `word_id`;
- учитывать `lang` и `reason` в локальной сигнатуре дедупликации событий;
- вывести на карточке урока по одной батарее и значение `learnedWords / totalWords` для каждого элемента `languageProgress`;
- карточку урока строить в три столбца: первый занимает 50% ширины и содержит название с компактным количеством слов, второй содержит батареи и `learnedWords/totalWords` по языкам, третий содержит чекбокс;
- во втором столбце каждый язык занимает отдельную строку: `батарея | код языка | learnedWords`; строки языков располагаются вертикально друг под другом, а `totalWords` используется только для расчёта заполнения батареи и в UI не выводится;
- батарею, код языка и счётчик выводить компактно без растягивающего промежутка; весь блок языков выравнивать по правому краю второго столбца;
- отдельную строку `Words: N` не показывать;
- после успешной синхронизации прогресса обновлять список уроков.

Критерии проверки Android:

1. При UI-языке `en` и выбранных языках `en`, `nl`, `ru` карточка показывает только `nl` и `ru`.
2. Правильная сборка одного слова на `nl` показывает `1 / N` только для `nl`.
3. Повторная сборка этого слова не меняет `1 / N` на `2 / N`.
4. Сборка того же слова на `ru` независимо меняет русский счётчик.
5. После синхронизации карточка и уровень батареи обновляются без удаления локального кэша.

### Автоматическое завершение урока

После `POST /api/progress/sync` сервер проверяет уроки, для которых пришёл новый `answer_ok`. Если на всех изучаемых языках заполнены все доступные слова, урок автоматически получает `hidden = 1` и считается выученным. Язык интерфейса не участвует в проверке. Языки, для которых в уроке нет ни одного слова (`total_words = 0`), также не блокируют завершение.

Ответ синхронизации дополнен полем:

```json
{
  "ok": true,
  "stored": 1,
  "completed_lessons": ["Animals"]
}
```

Android должен после успешной синхронизации применить обновление уроков либо повторно получить `GET /api/lessons`, чтобы автоматически завершённый урок переместился в скрытые/выученные.

## 13. 2026-07-04 — детский режим: 25 слов в день и освоение после 10 повторений

Изменение реализовано одновременно на сервере, в Telegram Web App и в Android-клиенте.

### Пользовательский сценарий

- Для детского аккаунта удалён таймер обучения на 10 минут.
- Вместо таймера показывается дневная цель: `25` правильно собранных слов.
- Дневной прогресс считается по локальному календарному дню устройства ребёнка.
- Одна правильная сборка увеличивает дневной счётчик на одно слово.
- Одно и то же слово можно успешно собрать не более `10` раз за всё время.
- После десятой правильной сборки слово считается выученным и исключается из дальнейшего обучения.
- Одиннадцатая и последующие правильные сборки этого слова сервером не учитываются.
- Повторное нажатие кнопки проверки для уже проверенного ответа не создаёт дополнительный прогресс.
- Для обычных аккаунтов новая детская дневная цель не отображается.

Награды за дневной прогресс:

- `5` слов — `Хороший старт 🌱`;
- `10` слов — `Молодец ⭐`;
- `15` слов — `Умница 🚀`;
- `20` слов — `Герой 🦸`;
- `25` слов — `Чемпион дня 🏆`.

До достижения пяти слов показывается только счётчик. После достижения порога показывается последний достигнутый статус. На следующий локальный календарный день дневной счётчик и статус начинаются заново, но накопленные повторения каждого слова сохраняются.

### Правила серверного подсчёта

Константы серверной логики:

```python
CHILD_DAILY_WORD_GOAL = 25
CHILD_WORD_MASTERY_COUNT = 10
```

Источником данных остаётся таблица `progress_events`. Учитываются правильные события обучения:

- Web: `scope = "learn"` и `state.reason = "answer_ok"`;
- Android: `scope = "learn"` и `event_type = "word_correct"`.

События обрабатываются по `event_ts`, затем по `id`. Для каждого `word_id` принимаются только первые десять правильных событий. Это правило используется одновременно для:

- общего количества повторений слова;
- определения выученных слов;
- дневного счётчика;
- родительской статистики `mastered_words`;
- количества правильных ответов в родительском дашборде.

Старое правило из раздела 12 «одно правильное событие означает выученное слово» для детского режима больше не применяется. В детском режиме слово считается выученным только после десяти правильных сборок. Для остальных аккаунтов существующая логика прогресса уроков не изменена.

### Новый API

`GET /api/child-learning/status?tz_offset=-120`

`tz_offset` передаётся в формате JavaScript `Date.getTimezoneOffset()`: количество минут, которое нужно прибавить к локальному времени, чтобы получить UTC. Например, летом для Amsterdam браузер передаёт `-120`.

## 19. 2026-07-06 — кэш переводов и озвучки Android

## 23. 2026-07-13 — накопительная статистика AI-токенов
